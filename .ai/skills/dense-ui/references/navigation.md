# Navigation, tabs, and surfaces

Global navigation names application domains. Local tabs name stable peer sections of the current record/workflow. Breadcrumbs show hierarchy. Contextual actions operate on the current record. Recents, favorites, and command/search affordances reduce repeated navigation but do not replace visible orientation.

Use tabs only for stable peer sections of the same entity, such as Overview, History, Financials, Maintenance, and Documents. Use sections when content must be compared together. Do not use tabs to conceal poor information architecture.

Tabs use a 36px desktop height, visible active underline/contrast, keyboard arrow navigation when implemented as a tablist, overflow into a labelled menu on narrow screens, and preserved focus/selection on navigation. Touch uses 44px targets.

## Page decision

- Dedicated page: complex, multi-step, high-consequence, or stateful workflow.
- Drawer: contextual inspection or bounded edit where the list/plan remains useful.
- Modal: short focused decision, confirmation, or small form.
- Popover/inline: lightweight local operation with immediate save/undo.

Never place a complex purchase order, multi-step receiving, or high-risk workflow inside a small modal.
