# Principles and evidence boundaries

## Dense-first principle

Dense is the default desktop system. Comfortable/cozy/relaxed language describes touch, tablet, mobile, accessibility, or intentionally low-density exceptions. It is not a peer default mode. Density comes primarily from removing wasted space, grouping related information, efficient tables, progressive disclosure, predictable actions, and short navigation paths—not indiscriminate shrinking.

## Evidence labels

- **FACT:** explicitly documented by the source.
- **OBSERVATION:** visible in official/public UI material.
- **INTERPRETATION:** reasoned operational lesson from the evidence.
- **RULE:** final Dense UI decision for a new product.

Never present an interpretation as a vendor mandate. The evidence matrix is in `enterprise-references.md`.

## Global rules

1. Information priority determines layout and responsive behavior.
2. Primary identity appears first and remains available at narrow widths.
3. Tables are the default comparison surface for repeated structured records.
4. Routine statuses stay quiet; exceptional statuses dominate only when action is required.
5. Structural borders and dividers carry ordinary grouping; shadows signal real elevation.
6. Cards are reserved for independently meaningful, selectable, dashboard, or strongly separated contexts.
7. Page headers are compact and operational, never marketing hero blocks.
8. Forms group related fields with visible labels and predictable keyboard order.
9. Semantic color communicates meaning, never decoration or color alone.
10. Repeated operations minimize clicks, navigation, typing, and confirmation overhead.
11. Keyboard workflows are first-class; touch workflows enlarge targets without discarding dense information grouping.
12. Accessibility, error recovery, and safe operation override visual density.
